## ลำดับระยะ

ปรับจากสเปกตามหลักฐานใน repo: ความเสี่ยงเงิน/สิทธิ์มาก่อน อย่าสร้าง POS ใหม่ทับ `sc_sales` จนกว่าจะมีสะพานข้อมูล

### ระยะ 1 — อุดความเสี่ยง + สูตรเงินกลาง (เริ่มแล้ว 2026-09-19)

- ย่อเอกสารถาวร · แยกประวัติ
- `lib/money.ts` + `test:money` · ห่อ `money()` / `settleDocumentVat` ให้ใช้สตางค์ข้างใน
- **ยังไม่ทำ:** ย้ายทุก `parseFloat` · ตาราง legal entity · apply production

เกณฑ์รับ: `test:money` `test:vat` `test:wht` `test:guards` ผ่าน · ผลลัพธ์เคส 1000/18000 เท่าเดิม

### ระยะ 2 — ธุรกรรม / idempotency / กันสต๊อกเกิน (เขียนใน repo 2026-09-19 — ยังไม่ apply production)

- `0044` + `test-migration-0044.mjs`: ปฏิเสธเบิกเกินก่อน trigger ถัวเฉลี่ย · อนุมัติปรับลดใช้ `fn_consume_stock_outflow` · unique `(tenant_id, client_request_id)` บน `sc_sales` / `sc_payments`
- แอปส่งคีย์จากฟอร์มยอดขายรายวัน · กดซ้ำได้ผลชุดเดียวถ้าคอลัมน์ถูก apply แล้ว
- เทสต์ PGlite เป็นลำดับต่อกันบน connection เดียว (ชิ้นสุดท้ายสำเร็จครั้งเดียว) — ยังไม่ใช่สอง connection จริง

เกณฑ์รับบนร้านจริง: apply `0044` หลังเจ้าของสั่ง + ของชิ้นสุดท้ายสำเร็จได้หนึ่งรายการ

### ระยะ 3 — POS–สต๊อก–รับชำระ end-to-end

เชื่อมหรือกำหนดชัดว่าเส้นทางไหนเป็นทางการ (`service_orders` vs `sc_sales`) ห้ามมีสองยอดความจริงโดยไม่กระทบยอด

### ระยะ 4 — เอกสาร ลูกหนี้ เจ้าหนี้ correction

draft ไม่กินเลข · void · ใบลดหนี้/เพิ่มหนี้ · snapshot คู่ค้า

### ระยะ 5 — ภาษี reconciliation ปิดงวด

ภาษีซื้อ · working paper · ล็อกงวด — ห้ามเรียกว่าพร้อมยื่นก่อนกระทบยอด

### ระยะ 6 — Dashboard UX performance

หลังสูตรและธุรกรรมนิ่งแล้วเท่านั้น

## มติที่ตอบแล้ว (2026-09-19) และของที่ยังต้องอนุมัติ

ตอบจากหลักฐานใน repo แล้ว (ดูตารางใน `CLAUDE.md`):

1. สาขา ≠ นิติบุคคลโดยอัตโนมัติ · tenant = กิจการในระบบ · VAT ต่อสาขาเป็นค่าตั้ง · เลขผู้เสียภาษีคงที่ tenant
2. ยอดขายทางการ = `sc_sales` + `sc_payments` · `service_orders` เป็นใบรับงาน
3. เบิกเกินสต๊อก = ปฏิเสธที่ DB (ยังไม่ลงมือ — ต้องมีเทสต์สอง connection ก่อน)
4. DRAFT ที่ไม่มีใบวางบิลอ้าง ลบได้ · บิลที่แปลง/ออกแล้วใช้ void เมื่อมี workflow · เลขที่ลบแล้วไม่คืน

ยังต้องอนุมัติก่อนลงมือ:

5. นโยบายคืนสินค้า: ต้นทุนจากบิลเดิมหรือต้นทุนปัจจุบัน?
6. อนุญาตให้ apply migration กันสต๊อกเกินบน production เมื่อใด?
