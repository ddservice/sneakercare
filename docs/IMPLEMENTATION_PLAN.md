## ลำดับระยะ

ปรับจากสเปกตามหลักฐานใน repo: ความเสี่ยงเงิน/สิทธิ์มาก่อน อย่าสร้าง POS ใหม่ทับ `sc_sales` จนกว่าจะมีสะพานข้อมูล

### ระยะ 1 — อุดความเสี่ยง + สูตรเงินกลาง (เริ่มแล้ว 2026-09-19)

- ย่อเอกสารถาวร · แยกประวัติ
- `lib/money.ts` + `test:money` · ห่อ `money()` / `settleDocumentVat` ให้ใช้สตางค์ข้างใน
- **ยังไม่ทำ:** ย้ายทุก `parseFloat` · ตาราง legal entity · apply production

เกณฑ์รับ: `test:money` `test:vat` `test:wht` `test:guards` ผ่าน · ผลลัพธ์เคส 1000/18000 เท่าเดิม

### ระยะ 2 — ธุรกรรม / idempotency / กันสต๊อกเกิน (apply production 2026-09-19)

- `0044` + `test-migration-0044.mjs`: ปฏิเสธเบิกเกินก่อน trigger ถัวเฉลี่ย · อนุมัติปรับลดใช้ `fn_consume_stock_outflow` · unique `(tenant_id, client_request_id)` บน `sc_sales` / `sc_payments`
- แอปส่งคีย์จากฟอร์มยอดขายรายวัน · กดซ้ำได้ผลชุดเดียวถ้าคอลัมน์ถูก apply แล้ว
- `test:stock-concurrency`: สองคำสั่งตัดสต๊อกพร้อมกันบน qty=1 — สำเร็จได้หนึ่งรายการ ยอดสุดท้ายเป็น 0 · PGlite คิวคำสั่ง ไม่ใช่สอง session ของ Postgres จริง

เกณฑ์รับบนร้านจริง: apply `0044` หลังเจ้าของสั่ง + ของชิ้นสุดท้ายสำเร็จได้หนึ่งรายการ

### ระยะ 3 — POS–สต๊อก–รับชำระ (สะพานบัญชี 2026-09-19)

- `/pos` ที่ชำระแล้วลงแถวขายหนึ่งใบ (`client_request_id` = `service_orders.id`) · จ่ายตอนรับยังไม่ลงบัญชี
- `0045` เพิ่ม `service_order_id` สำหรับรายงาน — **apply production แล้ว 2026-09-19** · `/pos` เขียนคอลัมน์นี้ · ยอดขายรายวันไม่ใส่ · ไม่แตะแถวเก่า
- คลังยังเบิกมือที่ `/stock-out` · สูตรของใช้ต่องานอยู่ที่ `/settings` แต่ `LIVE_AUTO_ISSUE_ALLOWED = false`
- เกณฑ์รับสูตร: `npm run test:checkout` · `test-migration-0045.mjs`

ยังไม่ทำ: ตัดสต๊อกคู่กับขายในธุรกรรมเดียว · tendered/change

### ระยะ 4 — เอกสาร ลูกหนี้ เจ้าหนี้ (ยกเลิก + ใบลดหนี้ชั้นเอกสาร 2026-09-19)

- ลบได้เฉพาะร่างที่ยังไม่มีคนอ้าง และไม่ใช่ใบกำกับ/ใบเสร็จ · CN/DN เลข `DRAFT-` ลบได้ · ที่เหลือใช้ `VOID` เก็บเลข
- ใบลดหนี้/เพิ่มหนี้อ้าง INV/TAX/REC · รวมลดหนี้ไม่เกินต้นทาง (+ DN) · ต้นทางไม่ถูกตั้ง `CONVERTED`
- เกณฑ์รับ: `npm run test:docs` — ไม่แตะ `sc_sales` และไม่คืนสต๊อก · ออกเลข CN/DN ทางการไม่ได้จนกว่าจะเชื่อมยอดขาย/ลูกหนี้/ภาษี
- snapshot ผู้ขายฝังตอนสร้างเอกสาร — ใบเก่าที่ไม่มีภาพใช้ร้านปัจจุบัน
- ร่าง QA/DO/INV/BL/CN/DN ใช้เลข `DRAFT-` · กดออกเลขแล้วจึงกินตัวนับ · TAX/REC กินเลขตอนสร้าง · **CN/DN ออกเลขถูกบล็อกฝั่งเซิร์ฟเวอร์**
- **ยังไม่ทำ:** CN กลับรายการขาย/คลัง/ลูกหนี้ · apply/deploy

### ระยะ 5 — ภาษี reconciliation (กระดาษทำงาน + ปิดงวด 2026-09-19)

- `lib/tax-recon.ts` เทียบยอดขายร้านกับเอกสารที่ออกแล้ว · ไม่นับ VOID / เลขร่าง / แปลงแล้ว · หักใบลดหนี้ บวกใบเพิ่มหนี้ · `readyToFile` เป็น false เสมอ
- `lib/pp30-paper.ts` กระดาษทำงาน ภ.พ.30 ช่อง 1–12 ตามแบบกรมสรรพากร (ตรวจ PDF ทางการ 2026-09-19) — สมุดขายจากใบกำกับ+CN/DN · ยังไม่ใช่แบบยื่น
- `lib/pp30-filing.ts` แยกสถานะเตรียมข้อมูลแล้ว vs ยื่นแล้ว · ยื่นแล้วต้องมีผู้ยื่น วันยื่น หลักฐาน และคำยืนยันว่ายื่นที่เว็บสรรพากร
- `lib/etax-pipeline.ts` คิว sandbox + adapter · XML/HTTP 200 ไม่ใช่ส่งสำเร็จ
- `lib/receipt-staging.ts` คิวใบเสร็จ จำแนกสินค้า/ค่าใช้จ่าย/สินทรัพย์ · แยกเครดิต VAT · ลงสมุดหลังอนุมัติและ idempotent
- เกณฑ์รับ: `npm run test:tax-recon` · `test:etax` · `test:receipts` · `test:period-close`
- ภาษีซื้อนับจากใบหัก ณ ที่จ่ายที่มี VAT + ใบเสร็จที่กรอกเอง + staging ที่อนุมัติและยืนยันเครดิต — ไม่นับ OCR ที่ยังไม่ตรวจ · ยังไม่ใช่สมุดซื้อเต็ม
- `0046` **apply production แล้ว 2026-09-20** · ตาราง unique ลงสมุด + ปิด live ที่ DB · คิวยังใช้ JSON+CAS ใน `sc_settings`
- ปิดงวดเก็บใน `sc_settings` · ค่าเริ่มต้นไม่ปิด · ปิดแล้วห้ามแก้บัญชีร้าน · ปิดแล้วก็ยังไม่พร้อมยื่น
- **ยังติดเงื่อนไขภายนอก:** e-Tax ส่งจริง (ช่องทาง+credentials+หลักฐานรับ) · ภ.พ.30 ยื่นจากแอป (login เว็บสรรพากร + คำสั่งอนุมัติ) · OCR ในแอป

4. ร่างที่ไม่มีใบวางบิลอ้างลบได้ (ไม่รวมใบกำกับ/ใบเสร็จ) · ที่แปลง/ออกแล้วใช้ยกเลิก เก็บเลข · เลขที่ลบแล้วไม่คืน

ยังต้องอนุมัติก่อนลงมือ:

5. นโยบายคืนสินค้าเมื่อเปิดคืนสต๊อกจริง: ต้นทุนจากบิลเดิม (สูตรปัจจุบันบังคับข้อนี้และรอถ้าไม่มีข้อมูล) หรือต้นทุนปัจจุบัน?
6. จุดตัดสต๊อกอัตโนมัติ: รับงาน / เริ่มงาน / ปิดงาน — และวิธียกเลิกเมื่อใช้จริงต่างจากสูตร
7. ช่องทาง e-Tax จริง (ผู้ให้บริการ + credentials + รูปแบบหลักฐานตอบรับ)
8. จะให้แอปช่วยยื่น ภ.พ.30 ที่เว็บสรรพากรหรือบันทึกหลักฐานการยื่นมือต่อไป
9. OCR: ผู้ให้บริการภายนอกใด หรือรับวางผลอย่างเดียว
10. อนุญาตให้ apply/deploy เมื่อใด — ห้ามสมมติว่าส่งภาษีหรือตัดสต๊อกแล้ว
