## ทำไมต้องแตก

`sc_opex` เป็นตารางเดียวที่เก็บของ **20 รูปแบบ** ปนกัน แยกกันด้วย `category`/`key` ที่เป็น
free-text ไม่มี enum บังคับที่ระดับฐานข้อมูล — บั๊กเรื่องเงินทุกตัวที่เจอมามีต้นตอเดียวกันหมด:

| บั๊กที่เคยเกิด | เกิดเพราะ |
|---|---|
| หน้าภาพรวมนับค่าใช้จ่ายขาด ฿6,600.51/เดือน | whitelist ชื่อหมวดที่ผู้ใช้ตั้งเองได้ |
| รายรับห้องเช่าถูกนับเป็นรายจ่าย | filter เช็คชื่อ category ผิดตัว (`rental_meter` vs `rental_income`) |
| เงินเดือนถูกนับซ้ำ ~฿27,275 | แถว `emp_*` ผ่าน filter หลักเข้าไปนับใน OPEX ด้วย |
| ลบรายการย่อยเบ็ดเตล็ดไม่ได้ | id สังเคราะห์ `"<rowId>-misc-<idx>"` เทียบกับ `id` ที่เป็น bigint |
| timestamp โผล่ในคอลัมน์ `amount` | ไม่มี constraint กันช่วงค่า |
| ค่าที่ปรึกษา = เงินเดือนหุ้นส่วน ที่ตั้งชื่อคนละอย่างทุกเดือน | `name` เป็น free-text ไม่มีตัวอ้างอิงพนักงานจริง |
