# รับซื้อวัสดุสิ้นเปลืองและเทียบราคา

อัปเดต 2026-11-04 · โค้ดในรีโป · migration 0047 ยังไม่ apply production

## วิธีเก็บถุงรองเท้า

- สินค้า = รูปแบบที่ใช้แทนกันได้ เช่น ถุงหูรูดผ้า สีดำ 30×40 ซม. หน่วยฐาน “ใบ”
- ต่างขนาด วัสดุ หรือรูปแบบ ให้สร้างคนละสินค้า อย่าเปลี่ยนหน่วยฐานของสินค้าเดิมที่มีประวัติแล้ว
- ซื้อซ้ำร้านใหม่หรือแพ็กขนาดใหม่ ใช้สินค้าเดิม แต่กรอกร้านและจำนวนต่อแพ็กของครั้งนั้น
- ตัวอย่าง 2 แพ็ก × 100 ใบ ค่าสินค้า 400 + ส่ง 40 − ลด 20 = รับเข้า 200 ใบ จ่าย 420 บาท ต้นทุนซื้อ 2.10 บาทต่อใบ
- ถ้าซื้อเป็นใบ กรอกหน่วยซื้อ “ใบ” และจำนวนต่อหน่วยซื้อ = 1
- บิลหลายสินค้า แบ่งค่าส่ง/ส่วนลดเฉพาะรายการก่อนบันทึก ไม่ใส่ยอดรวมบิลซ้ำทุกสินค้า

## เมนู

คลัง → เพิ่มสินค้าเข้าคลัง (`/stock-in`) → บันทึกซื้อ → ราคาซื้อ / ร้านค้า (`/stock-in/prices`)

ประวัติเก็บวันที่ซื้อ ชื่อร้าน snapshot สินค้า/หน่วยซื้อ จำนวนแพ็ก จำนวนต่อแพ็ก จำนวนฐาน ค่าสินค้า ค่าส่ง ส่วนลด ยอดสุทธิ และเลขบิล/ลิงก์ร้าน/หมายเหตุ

ราคาต่อหน่วย = ยอดสุทธิ ÷ จำนวนฐาน ราคาเฉลี่ย = ผลรวมยอดสุทธิ ÷ ผลรวมจำนวนฐาน ไม่เฉลี่ยราคาต่อบิลตรง ๆ

แสดงราคาต่ำสุด/สูงสุด/เฉลี่ยรายเดือน และเปรียบเทียบร้านด้วยราคาซื้อล่าสุดในช่วงที่เลือก พร้อมวันที่และจำนวนซื้อ ราคาที่แสดงเป็นข้อมูลอดีต ต้องสอบถามราคาปัจจุบันและดูคุณภาพประกอบ รายการได้ฟรีไม่ใช้แนะนำร้าน

เทียบเฉพาะสินค้าและหน่วยฐานเดียวกัน แยกสาขา ช่วงเริ่มต้น 365 วัน เลือกได้ไม่เกิน 366 วัน จำกัด 5,000 รายการ ถ้าเกินต้องลดช่วงวันที่ ไม่สรุปจากข้อมูลที่ถูกตัดทิ้ง

## ฐานข้อมูลและขอบเขต

- `0047_purchase_receipts.sql`: ตาราง `inv_purchase_receipts` ไม่มี grant ให้ client / RLS เปิด / แก้หรือลบไม่ได้
- อ่านและเขียนผ่าน RPC ที่ตรวจผู้ใช้ active, role, tenant และสาขา ผู้ช่วยใช้ได้เฉพาะสาขาตนเอง Staff และ anonymous ไม่มีสิทธิ์ดูต้นทุน
- ฟังก์ชันเป็น SECURITY DEFINER โดย role `inv_purchase_owner` ที่ NOLOGIN, ไม่ได้ BYPASSRLS และได้รับเฉพาะสิทธิ์ที่จำเป็น ตรวจสิทธิ์ผู้ใช้ก่อนทุกครั้ง
- รับเข้า สร้างสินค้าใหม่ และประวัติซื้ออยู่ในธุรกรรมเดียว มี request ID กันซ้ำและปฏิเสธคีย์เดิมที่เปลี่ยนข้อมูล มี audit ทั้ง ledger เดิมและ receipt ใหม่
- สต๊อกรับเข้า ณ เวลาบันทึก วันที่ซื้อใช้วิเคราะห์ราคา ไม่ replay สต๊อกย้อนหลัง ต้นทุนคลังยังใช้ moving average ผ่าน trigger เดิม และเก็บต้นทุนต่อหน่วย 4 ตำแหน่ง ส่วนสถิติใช้ยอดจ่ายจริงใน receipt
- ยังไม่ลง `sc_opex` หรือภาษีซื้ออัตโนมัติ ต้องบันทึกตาม workflow ค่าใช้จ่ายเดิม
- ไม่ backfill หมายเหตุเก่ามาเดาชื่อร้านหรือจำนวนต่อแพ็ก ไม่แก้ ledger เดิม
- ยังไม่มี workflow แก้รายการซื้อพร้อมกลับสต๊อก; ห้ามแก้/ลบ receipt ตรง ๆ รายการผิดต้องให้ผู้ดูแลตรวจและทำรายการชดเชยตาม ledger เดิม

## เวอร์ชันและการทดสอบ

Next.js / eslint-config-next 16.4.5 · React / React DOM 19.3.1 · Node.js LTS 26.13.0 (`.nvmrc`, package engines, CI)

แพตช์ dependency ที่ไม่ข้ามรุ่นติดตั้งแล้ว shadcn CLI อยู่ devDependencies; `npm audit --omit=dev` พบ 0 รายการ ส่วนรวมเครื่องมือพัฒนายังมี 21 รายการระดับต่ำ/ปานกลาง ไม่ใช้ `audit fix --force` ที่เสนอ downgrade เครื่องมือ

เครื่อง Windows นี้มี Node 26.13.0 แบบ portable ที่ `.tools/node-v26.13.0-win-x64` ตรวจ SHA256 จาก nodejs.org แล้ว โฟลเดอร์นี้ไม่เข้า git และไม่เปลี่ยน Node ทั้งเครื่อง ใช้ PowerShell ในโฟลเดอร์งาน:

```powershell
$env:Path = (Join-Path (Get-Location) '.tools/node-v26.13.0-win-x64') + ';' + $env:Path
node --version
npm run dev
```

เครื่องอื่นติดตั้ง Node ตาม `.nvmrc` ก่อน `npm ci` VPS ติดตั้ง portable Node26.13.0 แล้ว การสลับ PM2 อยู่ใน release ก่อนปล่อยต้องตรวจ Node ของทั้ง build และ PM2 ให้ตรงกัน

`npm run test:purchases` ทดสอบสูตรและ migration บน PGlite ทั้ง unprefixed tables และ inv_* + aliases ใช้ authenticated/anon จริงในฐานจำลอง ทดสอบ replay, payload conflict, ข้าม tenant, staff, audit และ rollback หลัง stock insert พัง ไม่ใช่เทสต์สอง connection ของ PostgreSQL จริง

`npm run test:purchases:ui` ใช้ Edge headless บน Windows พร้อม HTTP Supabase fixture ในเครื่อง เปิดพอร์ต 3007 / 54329 ต้องว่าง ก่อนทดสอบสร้าง build ด้วยค่าจำลองเหล่านี้ **ห้ามใช้ build ที่ชี้ฐานข้อมูลจริง**:

```powershell
$env:NEXT_PUBLIC_SUPABASE_URL = 'http://127.0.0.1:54329'
$env:NEXT_PUBLIC_SUPABASE_ANON_KEY = 'fixture-anon-key'
$env:SUPABASE_SERVICE_ROLE_KEY = 'fixture-service-role'
$env:NEXT_PUBLIC_SITE_URL = 'http://127.0.0.1:3007'
npm run build
npm run test:purchases:ui
```

ภาพและ log อยู่ใน `.scratch-ui/` / `.scratch-*.log` ไม่เข้า git ข้อมูลทั้งหมดใน browser fixture เป็นข้อมูลจำลอง หลังทดสอบให้เปิด terminal ใหม่เพื่อกลับไปใช้ `.env.local` และ build ใหม่ก่อนใช้งานจริง
