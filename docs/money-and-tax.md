# เงิน ภาษี และการปัดเศษ

อ่านไฟล์นี้เมื่อแตะยอดเงิน VAT WHT เอกสารขาย หรือรายงานภาษี  
สูตรที่ใช้ในโค้ดอยู่ที่ `lib/money.ts` · `lib/vat.ts` · `lib/wht.ts`

ตรวจแหล่งทางการของกรมสรรพากร **ก่อน** เปลี่ยนพฤติกรรมภาษี บันทึก URL + วันที่ตรวจ  
ถ้ายืนยันไม่ได้ ให้เขียนเป็นข้อจำกัดใน `HANDOFF.md` ห้ามเดาข้อกฎหมาย

---

## นโยบายที่พบในระบบ (2026-09-19) — ยังไม่ใช่ประกาศบัญชีฉบับใหม่

| หัวข้อ | ของจริง | หลักฐาน |
|---|---|---|
| ชนิดในฐานข้อมูล | คอลัมน์เงินส่วนใหญ่เป็น `numeric(12,2)` ต้นทุนคลัง `numeric(14,4)` จำนวนคลัง `numeric(14,3)` | migrations `0012`, `0001`, `0042` |
| ปัดเศษในแอปเดิม | `Math.round(n * 100) / 100` บน JavaScript number (`lib/wht.ts` เดิม, dashboard, expenses) | grep `Math.round` |
| นโยบายที่ล็อกในระยะ 1 | จำนวนเต็มสตางค์ + สตริงทศนิยม 2 ตำแหน่ง · HALF_UP · ≥ 0 | `lib/money.ts` + `npm run test:money` |
| VAT ขาย | ค่าคงที่ 7% ของฐาน**ไม่รวม** VAT ถ้าสาขาจด VAT และประเภทเอกสารคิด VAT | `STANDARD_VAT_RATE` · `settleDocumentVat` |
| สาขาไม่จด VAT | อัตรา 0 · ออกใบกำกับภาษีไม่ได้ | `lib/vat.ts` · `lib/branch-vat.ts` |
| QA / DO | ไม่คิด VAT | `NEVER_VAT` |
| INV / BL / REC | เลือกบิลเงินสดหรือบิล VAT ต่อใบ | `OPTIONAL_VAT` |
| TAX | บังคับ 7% ถ้าจด | `documentVatRate` |
| WHT | คิดจากฐานก่อน VAT · ไม่ใช่ส่วนลด · ไม่ลง `sc_opex` ซ้ำ | `settleWht()` |
| ค่าเช่าอาคาร | WHT เริ่มต้น 5% | `BUILDING_RENT_WHT_RATE` |

ยัง**ไม่มี**ตารางอัตรา VAT ตามวันมีผล (effective date)  
ยัง**ไม่มี**คอลัมน์ snapshot ชื่อผู้ขาย/เลขผู้เสียภาษีบน `ext_documents` — ตอนพิมพ์อ่าน `fetchShopProfile()` กับ `ext_contacts` สด

## ความหมายที่ต้องแยก

| คำ | ความหมายในระบบนี้ |
|---|---|
| บิลเงินสด | เอกสารขายอัตรา VAT 0% (ไม่ใช่แปลว่าจ่ายเงินสดแล้ว) |
| บิล VAT | เอกสารคิด 7% นอกราคา |
| ยกเว้น VAT / VAT 0% | **ยังไม่แยกชนิดใน schema** — ตอนนี้มีแค่ 0 หรือ 7 |
| ราคารวม VAT | มีสูตรใน `settleInclusiveVat` แล้ว แต่เอกสารขายยังไม่ใช้ |
| WHT | เงินที่หักจากยอดโอน เพื่อนำส่งสรรพากร — ไม่ใช่รายจ่ายเพิ่ม |

## สองสายเงินที่ต้องกระทบยอดด้วยกัน (อย่านับซ้ำ / อย่าทิ้งฝั่งหนึ่ง)

| สาย | ตาราง | หน้าที่ |
|---|---|---|
| คลัง | `inv_stock_transactions` | จำนวน + ต้นทุนถัวเฉลี่ย |
| จ่ายจริง | `sc_opex` | เงินออกจากร้านในเดือน |
| ขายรายวัน | `sc_sales` + `sc_payments` | รายรับที่หน้าภาพรวมใช้ |
| งานบริการ | `service_orders` | ใบรับงาน — จ่ายตอนรับยังไม่ลงบัญชี · เงินสด/โอน/บัตรลง `sc_sales` หนึ่งแถว (`client_request_id` = id ใบ) |
| เอกสารขาย | `ext_documents` | ใบแจ้งหนี้/กำกับ — **ยังไม่ลง `sc_sales` อัตโนมัติ** |

`npm run check:stock-vs-expenses` เทียบคลังกับค่าใช้จ่าย  
`npm run test:reconcile` เทียบกำไรรายเดือนกับ Excel ที่เคยกระทบไว้ (7 เดือน) — แตะสูตรเดิม ห้ามรันบนสมมติว่าผ่านโดยไม่รัน

## สิ่งที่ยังไม่ผ่านจึงห้ามเรียกว่าพร้อมยื่น

- กระดาษทำงานที่ `/tax-filing` เทียบยอดขายร้านกับเอกสารได้แล้ว แต่ `readyToFile` ยังเป็น false เสมอ
- กระดาษทำงาน ภ.พ.30 ช่อง 1–12 ตามแบบกรมสรรพากร ([ภ.พ.30 PDF](https://rd.go.th/fileadmin/tax_pdf/vat/pp30_300160.pdf) ตรวจ 2026-09-19) — สมุดขายนับใบกำกับภาษี + ใบเพิ่มหนี้ − ใบลดหนี้ · ช่อง 2–3 (0%/ยกเว้น) และช่อง 10 (ภาษีเกินยกมา) ยังเป็น 0 · ไม่คำนวณเงินเพิ่ม/เบี้ยปรับ · **ยังไม่ใช่แบบยื่น**
- ภาษีซื้อนับจากใบหัก ณ ที่จ่ายที่มี VAT และใบเสร็จที่กรอกเองที่ `/tax-filing` — ไม่นับ OCR จำลอง และยังไม่ใช่สมุดซื้อเต็ม
- ภ.พ.30 ยื่นโดยกรอกในเว็บ e-Filing ไม่ใช่ไฟล์แนบแบบ ภ.ง.ด.
- e-Tax XML ใน `/tax-filing` เป็นตัวอย่าง ไม่ได้ส่งและไม่มี log ใน `ext_etax_logs`
- ภ.ง.ด.3/53 สร้างไฟล์ FORMAT กลางจาก `sc_wht_certificates` — การรับรอง/ยื่นสำเร็จอยู่นอกระบบ
- ไม่มีสมุดรายวัน (GL)
- มีปิดงวดบัญชีร้านแล้ว (`sc_settings.closed_periods`) — ค่าเริ่มต้นยังไม่ปิดงวดใด · ปิดแล้วห้ามแก้ยอดขาย/รับชำระ/รายจ่าย · **ปิดงวดไม่ได้ทำให้พร้อมยื่น**
